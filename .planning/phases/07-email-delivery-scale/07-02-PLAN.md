<objective>
Build the Cloudflare Worker that handles RFC 8058 one-click unsubscribe POST requests and Resend webhook events (bounces, complaints).

Purpose: Gmail/Yahoo require a publicly accessible HTTPS POST endpoint for one-click unsubscribe. The project runs entirely on GitHub Actions with no server, so Cloudflare Workers (free, no cold starts, globally distributed) provides the endpoint. This worker also handles Resend webhooks to auto-deactivate bouncing/complaining subscribers for list hygiene.

Output: `unsubscribe-worker/` directory with TypeScript Cloudflare Worker, ready to deploy via `wrangler deploy`.
</objective>

<task type="auto">
  <name>Task 2: Implement Worker with unsubscribe + webhook routes</name>
  <files>unsubscribe-worker/src/index.ts</files>
  <action>
Create `unsubscribe-worker/src/index.ts` with the following routes:

1. **Environment interface:**
   ```typescript
   interface Env {
     UNSUBSCRIBE_SECRET: string;
     TURSO_URL: string;
     TURSO_TOKEN: string;
     RESEND_WEBHOOK_SECRET?: string;
     ENVIRONMENT: string;
   }
   ```

2. **Helper: `generateToken(email: string, secret: string) -> Promise<string>`:**
   - Use Web Crypto API (available in Workers): `crypto.subtle.importKey()` + `crypto.subtle.sign()`
   - HMAC-SHA256 with the secret key
   - Return hex-encoded first 32 chars (must match Python email_client.py implementation)
   - Normalize email: `email.toLowerCase().trim()`

3. **Helper: `deactivateSubscriber(email: string, env: Env, reason: string) -> Promise<boolean>`:**
   - POST to Turso HTTP API (`${env.TURSO_URL}/v2/pipeline`)
   - Headers: `Authorization: Bearer ${env.TURSO_TOKEN}`, `Content-Type: application/json`
   - Body: `{"requests": [{"type": "execute", "stmt": {"sql": "UPDATE subscribers SET active = 0, unsubscribed_at = datetime('now'), unsubscribe_reason = ? WHERE email = ? AND active = 1", "args": [{"type": "text", "value": reason}, {"type": "text", "value": email}]}}]}`
   - Return true on success, false on error (log error to console)

4. **POST /unsubscribe (RFC 8058 one-click):**
   - Extract `email` and `token` from URL search params
   - If missing email or token: return 400
   - Generate expected token via `generateToken(email, env.UNSUBSCRIBE_SECRET)`
   - If token mismatch: return 403 "Invalid token"
   - Call `deactivateSubscriber(email, env, "one-click-unsubscribe")`
   - Return 200 "Unsubscribed successfully"

5. **GET /unsubscribe (browser confirmation page):**
   - Extract `email` and `token` from URL search params
   - If missing: return 400
   - Verify token (same as POST)
   - Return HTML page with Detty branding (green/yellow/red gradient), showing:
     - "Unsubscribe from Detty Flight Deals"
     - Email address being unsubscribed (masked: f***@gmail.com)
     - A "Confirm Unsubscribe" button that POSTs to the same URL
     - "We're sorry to see you go" message
   - Use inline styles (no external CSS). Match Detty brand colors (#009639, #FCD116, #E31C25).

6. **POST /webhook/resend (bounce + complaint handler):**
   - Parse JSON body
   - Check `type` field:
     - `email.bounced`: Extract `data.to[0]`, call `deactivateSubscriber(email, env, "bounced")`
     - `email.complained`: Extract `data.to[0]`, call `deactivateSubscriber(email, env, "spam-complaint")`
     - Other types: return 200 (acknowledge but ignore)
   - Optional: Verify Resend webhook signature if `RESEND_WEBHOOK_SECRET` is set (using `svix` headers). If not set, skip verification (simpler initial setup).
   - Return 200

7. **GET / (health check):**
   - Return 200 with JSON: `{"service": "detty-unsubscribe", "status": "ok"}`

8. **Default: Return 404 for all other routes.**

**CRITICAL:** The HMAC token generation MUST match Python's `hmac.new(secret.encode(), email.lower().strip().encode(), hashlib.sha256).hexdigest()[:32]`. Test this by generating a token for "test@example.com" with secret "test-secret" in both languages and confirming they match. The Web Crypto API returns ArrayBuffer, so you need to convert to hex string manually.
