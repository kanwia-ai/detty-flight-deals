  <name>Task 1: Create LevelShiftDetector for sudden price drop detection</name>

  <action>
Create LevelShiftDetector implementing DISC-05 using custom pandas-based approach from RESEARCH.md.

Why custom (not ADTK): ADTK last updated April 2020, Python 3.11+ compatibility uncertain. Custom is simpler, testable, dependency-light.

Implementation from RESEARCH.md detect_level_shift pattern:
- short_window=3: Recent observations to compare (last 3 checks)
- long_window=14: Baseline period (previous 14 observations)
- threshold_pct=0.40: Percentage drop to trigger (40% drop)

Algorithm:
1. Compare median of recent short_window vs median of previous long_window
2. If drop_pct >= threshold_pct, flag as level shift (exceptional deal)

Class structure:
```python
class LevelShiftDetector:
    def __init__(self, short_window=3, long_window=14, threshold_pct=0.40):
        ...

    def detect(self, prices: pd.Series) -> dict:
        """
        Returns:
            {
                "is_level_shift": bool,
                "drop_pct": float or None,
                "recent_median": int,
                "baseline_median": int,
                "method": "level_shift" or "insufficient_data"
            }
        """
```

Also add standalone function for simple use:
```python
def detect_level_shift(prices: pd.Series, threshold_pct=0.40) -> bool:
    """Quick check - returns True if level shift detected."""
```

Edge cases to handle:
- len(prices) < short_window + long_window: return insufficient_data
- baseline_median == 0: return False (avoid division by zero)
  </action>
  <verify>
```python
import pandas as pd
from anomaly.level_shift_detector import LevelShiftDetector, detect_level_shift

# Test level shift detection - sudden drop from ~$1000 to ~$500
prices_with_shift = pd.Series([
    1000, 1050, 980, 1020, 990, 1010, 1000, 950, 1030, 980,  # 10 baseline obs
    1020, 990, 1000, 1010,  # 4 more baseline obs
    500, 480, 520  # 3 recent obs - ~50% drop
])

detector = LevelShiftDetector(short_window=3, long_window=14, threshold_pct=0.40)
result = detector.detect(prices_with_shift)

assert result["is_level_shift"] == True, f"Should detect 50% drop as level shift, got {result}"
assert result["drop_pct"] >= 0.40, f"Drop should be >= 40%, got {result['drop_pct']}"
print(f"Level shift detected: drop_pct={result['drop_pct']:.2%}")

# Test no level shift - stable prices
stable_prices = pd.Series([1000, 1050, 980, 1020, 990, 1010, 1000, 950, 1030, 980, 1020, 990, 1000, 1010, 990, 1000, 1010])
result2 = detector.detect(stable_prices)
assert result2["is_level_shift"] == False, "Stable prices should not trigger level shift"

# Test insufficient data
short_prices = pd.Series([1000, 500, 480])
result3 = detector.detect(short_prices)
assert result3["method"] == "insufficient_data", "Short series should return insufficient_data"

# Test standalone function
assert detect_level_shift(prices_with_shift) == True, "Standalone function should detect shift"

print("LevelShiftDetector tests passed")
```

Add get_price_history method to TursoClient for querying historical prices (needed for baseline calculations).

Method signature:
```python
def get_price_history(
    self,
    route: str,
    days: int = 90,
    cabin_class: str = "economy"
) -> list[dict] | None:
    """
    Get price history for a route from price_observations table.

    Args:
        route: Route string e.g. "JFK-LOS"
        days: Number of days of history to retrieve (default 90)
        cabin_class: Cabin class filter (default "economy")

    Returns:
        List of dicts with {date_checked, travel_date, price_cents}
        ordered by date_checked DESC, or None if Turso unavailable.
        Returns empty list if no observations found.
    """
```

SQL query:
```sql
SELECT date_checked, travel_date, price_cents
FROM price_observations
WHERE route = ?
  AND cabin_class = ?
  AND date_checked >= datetime('now', '-{days} days')
ORDER BY date_checked DESC
```

Note: SQLite datetime function works with ISO format timestamps stored as TEXT.

Returns None if Turso unavailable (callers should handle fallback).
Returns empty list [] if no observations exist for route.

Add to existing TursoClient class after get_alert_state method.
