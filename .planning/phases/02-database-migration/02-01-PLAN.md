<task type="auto">
  <name>Task 2: Create db/client.py with TursoClient</name>
  <files>db/client.py, db/__init__.py</files>
  <action>
Create `db/client.py` with TursoClient class following the patterns from 02-RESEARCH.md:

1. **Constructor** `__init__(self, dual_write: bool = True)`:
   - Check for TURSO_DATABASE_URL and TURSO_AUTH_TOKEN env vars
   - If missing: set `self._turso_available = False`, log warning, return
   - If present: connect using `libsql.connect(":memory:", sync_url=url, auth_token=token)`
   - Call `conn.sync()` to pull remote state
   - Initialize schema via `init_schema(conn)`
   - Set `self._turso_available = True`

2. **Retry decorator** for Turso operations:
   - Use `@retry(stop=stop_after_attempt(3), wait=wait_exponential(multiplier=1, min=1, max=10))`
   - Retry on ConnectionError, TimeoutError, OSError

3. **Core methods**:
   - `record_observation(route, date_checked, travel_date, return_date, price_cents, source, cabin_class, tier)` - INSERT into price_observations
   - `update_cache(route, tier, price_cents, dest_name)` - INSERT OR REPLACE into price_cache
   - `get_cache(route, tier)` -> dict or None - SELECT from price_cache
   - `update_alert_state(route, current_tier, cooldown_expiry)` - INSERT OR REPLACE into alert_state
   - `get_alert_state(route)` -> dict or None - SELECT from alert_state

4. **Fallback behavior**:
   - Each method checks `self._turso_available`
   - If False: return immediately (caller handles JSON fallback)
   - If True but operation fails: catch exception, log, set `self._turso_available = False` for this session

5. **Sync after writes**:
   - Call `self._conn.sync()` after every commit to push to Turso cloud
   - This is critical for GitHub Actions ephemeral environment

6. Update `db/__init__.py` to export TursoClient:
```python
from .client import TursoClient

__all__ = ["TursoClient"]
```

Do NOT use async - use synchronous API throughout (GitHub Actions doesn't need async).
