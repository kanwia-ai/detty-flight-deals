**Create `.github/workflows/priority_monitor.yml`:**

```yaml
name: Priority Route Monitor (Amadeus)

on:
  schedule:
    - cron: '15 */2 * * *'  # Every 2 hours at :15 past (avoid top-of-hour congestion)
  workflow_dispatch:  # Manual trigger for testing

concurrency:
  group: detty-state-commit
  cancel-in-progress: false  # Queue runs, don't cancel -- state files need to be committed

permissions:
  contents: write  # Allow pushing state files back to repo

jobs:
  monitor:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      - name: Install dependencies
        run: pip install -r requirements.txt

      - name: Run priority monitor
        env:
          AMADEUS_CLIENT_ID: ${{ secrets.AMADEUS_CLIENT_ID }}
          AMADEUS_CLIENT_SECRET: ${{ secrets.AMADEUS_CLIENT_SECRET }}
          AMADEUS_HOSTNAME: test  # Change to 'production' when ready for real data
          SMTP_EMAIL: ${{ secrets.SMTP_EMAIL }}
          SMTP_PASSWORD: ${{ secrets.SMTP_PASSWORD }}
          NOTIFY_EMAIL: ${{ secrets.NOTIFY_EMAIL }}
          GOOGLE_SHEET_ID: ${{ secrets.GOOGLE_SHEET_ID }}
          GOOGLE_SHEETS_CREDS: ${{ secrets.GOOGLE_SHEETS_CREDS }}
        run: python amadeus_monitor.py

      - name: Commit state files
        run: |
          git config --local user.email "action@github.com"
          git config --local user.name "GitHub Action"
          git pull --rebase origin main || true
          git add price_cache.json alert_cooldown.json price_history.jsonl 2>/dev/null || true
          git diff --staged --quiet || git commit -m "Update priority monitor state [skip ci]"
          git push || true
```

Key design decisions:
- cron at :15 past the hour (research recommendation: avoid top-of-hour congestion)
- concurrency group "detty-state-commit" shared with find_deals.yml (prevents git push conflicts from research Pitfall 4)
- cancel-in-progress: false so queued runs still execute (don't lose monitoring windows)
- git pull --rebase before push (handles concurrent state file updates)
- [skip ci] in commit message prevents infinite workflow triggers
- AMADEUS_HOSTNAME set to 'test' initially -- change to 'production' when ready
- Includes price_history.jsonl in git add (amadeus_monitor.py logs via log_price_search)
- All the same email secrets as find_deals.yml (needed for Google Sheets subscribers)

**Update `.github/workflows/find_deals.yml`:**

Add ONLY the concurrency group to the existing workflow. Do NOT change anything else. Add these lines right after the `on:` block (before `permissions:`):

```yaml
concurrency:
  group: detty-state-commit
  cancel-in-progress: false
```

Also update the commit step to include `git pull --rebase origin main || true` before git add (matching the priority monitor pattern). This prevents push failures when the priority monitor has committed since the workflow started.

The updated commit step should be:
```yaml
      - name: Commit state files
        run: |
          git config --local user.email "action@github.com"
          git config --local user.name "GitHub Action"
          git pull --rebase origin main || true
          git add seen_deals.json price_history.jsonl 2>/dev/null || true
          git diff --staged --quiet || git commit -m "Update deal state [skip ci]"
          git push || true
```

IMPORTANT: The concurrency group name MUST be "detty-state-commit" in BOTH workflows. This is what prevents the git push conflict described in research Pitfall 4.
IMPORTANT: Do NOT change the find_deals.yml cron schedule, env vars, or python command. Only add the concurrency group and update the commit step with git pull --rebase.
IMPORTANT: cancel-in-progress MUST be false. If set to true, queued runs would be cancelled and monitoring windows would be lost.
