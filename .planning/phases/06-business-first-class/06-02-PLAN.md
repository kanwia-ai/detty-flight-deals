  <name>Task 2: Create premium cabin monitor orchestrator</name>
  <files>premium_cabin_monitor.py</files>
  <action>
  Create `premium_cabin_monitor.py` at the project root. This is the main entry point for premium cabin monitoring, called by the GitHub Actions workflow.

  Structure it following the pattern of `amadeus_monitor.py` but with these differences:

  ```python
  """
  Detty Flight Deals - Premium Cabin Monitor
  Monitors Business, First, and Premium Economy fares on priority routes.

  Runs every 4-6 hours via GitHub Actions (separate from economy monitor).
  All premium cabin deals route exclusively to premium subscribers.

  BUSN-01: Monitor premium cabin fares via Amadeus cabin class parameter
  BUSN-02: Separate thresholds from economy (static fallback + z-score)
  BUSN-03: Premium cabin deals routed only to premium subscribers
  """
  ```

  Class: `PremiumCabinMonitor`

  Key attributes:
  - `_budget`: PremiumBudget instance
  - `_db`: TursoClient instance
  - `_fsm`: AlertStateMachine instance (with db_client)
  - `_router`: AlertRouter instance
  - `_baseline`: BaselineCalculator instance (with db_client)

  Key methods:

  1. `__init__(self)`: Initialize all components. Check if `PREMIUM_CABIN_MONITORING_ENABLED` env var is set (default "true"). If "false", log and set `self._enabled = False`.

  2. `run(self) -> dict`: Main entry point.
     - Check `self._enabled`; if False, print message and return empty summary
     - Check budget via `self._budget.is_exhausted()`; if exhausted, print and return
     - Calculate calls needed: `len(PRIORITY_ROUTES) * len(CABIN_CLASSES) * 12`
     - If `self._budget.remaining() < calls_needed`, print warning but continue with reduced scope (process routes until budget runs out)
     - Create Amadeus client via `create_amadeus_client()`
     - For each route in PRIORITY_ROUTES:
       - For each cabin in CABIN_CLASSES:
         - Check budget remaining >= 12 (calls for one route-cabin combo)
         - Call `search_offers_for_cabin(client, origin, dest, sample_dates, cabin)`
         - Record API calls to budget
         - For each price result, call `self._process_observation(origin, dest, cabin, price_data)`
     - Save budget
     - Return run summary dict

  3. `_process_observation(self, origin, dest, cabin_class, price_data) -> Optional[dict]`:
     - Record observation in Turso DB (`cabin_class` field = cabin_class.lower())
     - Build route key for FSM: `f"{origin}-{dest}:{cabin_class}"`
     - Classify deal via `self._baseline.classify_deal(price_cents, route, cabin_class=cabin_class.lower())`
     - If classification is None (no deal or silent period): feed normal price to FSM, return None
     - If deal detected:
       - Determine `is_mistake_fare` from classification method == "level_shift" or tier == "exceptional"
       - Process through FSM: `self._fsm.process(route_key, deal_tier, price_cents, is_mistake_fare)`
       - If FSM says alert:
         - Build deal dict (origin, dest, dest_name, price, tier, cabin_class, url, is_mistake_fare)
         - Route via `self._router.route_deal(deal)` -- AlertRouter already handles premium-only routing
         - Return deal dict
     - Return None

  4. `_build_google_flights_url(origin, dest, departure_date, cabin_class)`: Static method to build Google Flights URL with cabin class parameter. Google Flights uses `tfc=` param for travel class: `tfc=1` for Economy, `tfc=2` for Premium Economy, `tfc=3` for Business, `tfc=4` for First.

  Main entry `main()`:
  - Print banner with timestamp
  - Create PremiumCabinMonitor and call run()
  - Print summary

  ```python
  if __name__ == "__main__":
      main()
  ```

  IMPORTANT implementation details:
  - Use `generate_sample_dates()` from amadeus_client for the sample dates (same 12 dates, same strategy)
  - For the deal dict passed to AlertRouter, set `tier` to the actual display tier. Per CONTEXT.md, all premium cabin deals are treated like mistake fares: instant alert + SMS. So set `is_mistake_fare=True` for ALL premium cabin deals (not just level_shift detected ones). This ensures SMS delivery and premium-only routing.
  - Actually, re-reading CONTEXT.md more carefully: "Treat premium cabin deals like mistake fares: rare, high-value, each gets its own dedicated instant alert. Email + SMS for premium subscribers with phone numbers." This means the ROUTING should be like mistake fares, but the DISPLAY tier should still say "Business Class Deal" not "MISTAKE FARE". So: set `is_mistake_fare=False` in the deal dict but ensure the tier routes to premium-only. The AlertRouter already routes WOW deals to premium-only. So map premium cabin deals to tier="wow" for routing purposes. The email template (Plan 03) will add the cabin class context.
  - Log each route-cabin check result (no data, in silent period, deal found, no deal)
